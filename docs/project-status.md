## 当前主要缺口

### P0：公开部署前必须处理

1. **认证与授权**：请求中的 `user_id` 可由客户端提供；应改为服务端会话或可信身份系统。
2. **访问与滥用控制**：增加请求限流、上传配额、服务端身份绑定和反向代理访问策略。
3. **自动备份与恢复演练**：手动 JSON 恢复和 SQLite 快照已验证，仍需调度、保留和定期恢复演练。
4. **部署安全**：使用 HTTPS，限制 `CORS_ORIGINS`，持久化挂载数据库、上传和备份目录。

### P1：建议在正式 1.0 前处理

1. 前端主包约 630 kB，Vite 存在大于 500 kB 的 chunk 警告；可对统计和数据管理模块做动态加载。
2. 增加 ESLint、格式化检查和前端单元测试。
3. 补充 Docker / Compose 或 systemd/PM2 部署示例。
4. 引入数据库迁移版本管理、结构化日志和错误追踪。
5. 扩展移动端、无障碍和跨浏览器回归。

## 对外表述

推荐：

- `v0.9.0 Beta`
- `self-hosted food diary`
- `React + Express + SQLite`
- `local-first identity for trusted sharing`

不建议宣称：

- 生产级身份认证
- 多租户 SaaS
- 可直接裸露公网
- 自动灾备或完全离线

正式进入 `v1.0.0` 前，应至少完成认证授权、访问控制、自动备份与恢复演练。
